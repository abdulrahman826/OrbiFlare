# 1. PROJECT OVERVIEW

**Purpose.** OrbiFlare ("Explainable Thermal Behaviour Intelligence", project code `SIH26162`) is an industrial-thermal-intelligence platform that ingests NASA FIRMS satellite active-fire detections (VIIRS/MODIS), OpenStreetMap-derived industrial facility context, and turns them into an explainable, human-reviewed investigation workflow — never an automated "confirmed fire" verdict.

**Core problem it solves.** Most systems treat a single satellite hotspot pixel as the unit of analysis. OrbiFlare instead treats the **evolving thermal event** as the unit of analysis: it learns what "normal" thermal behaviour looks like at a given industrial facility (a **Facility Thermal Twin**), measures how a live event's behaviour deviates from that baseline across six independent dimensions, fuses that deviation with a supporting ML signal into a structured **Evidence Stack**, computes an explainable **Risk** score and **Risk Trajectory**, and hands the whole aggregate to a human analyst through an **Investigation** page — with every alert-state change an explicit, audited operator action.

**Main analyst workflow** (as literally implemented, see §7):
Command Center (triage) → Events (filter/sort) → Investigation (full evidence/risk/trajectory) → Event Replay (chronological playback) → Operator Action (state transition) → Reports (export/incident report). The **Fire Intelligence Agent** (`/agent`) is a parallel, read-only query surface over the same computed data.

**Major differences / improvements visible in this version** (relative to what the codebase itself documents as deliberate choices, `docs/architecture.md`):
- Live NASA FIRMS ingestion is now actually wired end-to-end (`scripts/ingest_firms.py --live`, `app/ingestion/firms.py::ingest_from_live_api`), verified against the real FIRMS API in this session — not just a local-file adapter.
- The Fire Intelligence Agent is a **fully deterministic, read-only** intent-parser + controlled tool registry (`app/agent/deterministic.py`, `app/agent/tools.py`) — there is no LLM/Claude/Anthropic dependency anywhere in its execution path (this was explicitly removed; the codebase previously had an *optional* Claude-based phrasing-polish adapter, `app/agent/llm.py`, which has been deleted).
- New agent capabilities not present in the original scaffold: `list_persistent_events`, `facility_event_frequency`, `get_event_statistics`, `get_facility_statistics`, `get_risk_statistics`, `compare_event_to_baseline` — all read-only, all backed by real stored data.
- Explicit dual-provenance UI badges: `DemoBadge` ("DEMO / SYNTHETIC") and a newly-added `LiveBadge` ("LIVE / NASA FIRMS") so every event/observation on screen is unambiguously labelled as one or the other.
- `scripts/ingest_facilities.py` (OSM GeoJSON / WRI CSV loader) added to complete the real-data facility-context path.

**What makes the application distinctive** (per the codebase's own stated design goals, `docs/architecture.md`, `docs/limitations.md`, `app/intelligence/explanations.py`):
1. Living Thermal Events, not raw hotspot pixels.
2. A per-facility, robust-statistics behavioural baseline (Thermal Twin) that is explicitly labelled ESTABLISHED / LIMITED / INSUFFICIENT and never fabricated.
3. Six independently-computed deviation dimensions (never collapsed directly into a "fire probability").
4. A structured, four-bucket Evidence Stack with explicit correlation-flagging so correlated signals are never double-counted.
5. A primary hypothesis **plus genuine alternatives and unknowns** rather than one forced verdict.
6. A Risk Trajectory computed by literally re-running the whole pipeline on successive prefixes of an event's real observation history (never interpolated/fabricated).
7. A human-in-the-loop alert lifecycle state machine that the agent is *programmatically* forbidden from ever resolving.
8. Aggressive, code-enforced "scientific honesty" language (`app/intelligence/explanations.py::SCIENTIFIC_HONESTY_BANNED_PHRASES`).

# 2. COMPLETE FEATURE INVENTORY

### Command Center dashboard
- **Purpose:** operational triage overview across all monitored facilities.
- **User problem solved:** "what needs my attention right now" at a glance.
- **Where it appears:** `/command-center` (`frontend/src/app/command-center/page.tsx`), the landing redirect target of `/`.
- **How the user interacts:** read-only KPIs, a map, a scrollable priority feed; click any event card to drill into Investigation.
- **Inputs:** none (server component, fetches on load).
- **Outputs:** 5 KPI tiles (Active, High priority, Escalating, Persistent, Needs validation), a `MapPanel`, a 12-item risk-sorted `EventCard` feed, a "System status" strip (facility/baseline/demo counts).
- **Backend/API:** `GET /api/events`, `GET /api/facilities`, `GET /api/analytics/overview` (fetched in parallel via `Promise.all`).
- **Data involved:** all events + facilities + the analytics overview aggregate.
- **Implementation status:** IMPLEMENTED (real computation from stored data; KPI thresholds like "persistent" = `observation_count >= 6` are hardcoded client-side filters, not a stored field).
- **Dependencies:** `EventCard`, `KPI`, `MapPanel`, `Panel`.
- **Worth preserving:** MUST — this is the primary analyst entry point and is well-composed (KPI row → map+feed → status strip).

### Events list + filter/sort
- **Purpose:** browse/filter/sort the full event catalogue.
- **Where it appears:** `/events`.
- **Interaction:** four dropdown filters (Severity, Status, Trajectory, Classification) + a sort selector (Risk / Recency / Persistence); all client-side over an already-fetched list (`useMemo`).
- **Inputs:** filter/sort selections (client state only, not URL-persisted).
- **Outputs:** a responsive card grid of `EventCard`s, a live "N of M" count.
- **Backend/API:** `GET /api/events` (client-side fetch in a `"use client"` component, not server-rendered).
- **Status:** IMPLEMENTED. Note: the "Deviation" sort option in the `<select>` literally re-sorts by risk_score (`sortKey === "deviation"` branch falls through to the same comparator as `"risk"`) — this looks like a leftover/incomplete wiring rather than a real deviation-based sort.
- **Worth preserving:** MUST (the filter bar pattern), NICE (fix or remove the dead "deviation" sort option).

### Investigation page (full aggregate view)
- **Purpose:** the single, complete analyst workspace for one event — see §7 for the full traced workflow.
- **Where it appears:** `/investigation/[eventId]`.
- **Backend/API:** `GET /api/events/{id}/investigation` (one aggregate call).
- **Status:** IMPLEMENTED — every sub-panel (map, timeline, deviation table, evidence stack, alternative explanations, risk trajectory, ML evidence, uncertainty notice, operator actions) is real, wired to real computed data.
- **Worth preserving:** MUST — this is the product's centerpiece.

### Event Replay (index + player)
- **Purpose:** deterministic, chronological "PLAY EVENT" reconstruction of an event's real observation history.
- **Where it appears:** `/replay` (index list, sorted by risk, filtered to `observation_count >= 2`) and `/replay/[eventId]` (the player).
- **Interaction:** Play/Pause, step-back (`⏮`), step-forward (`⏭`), and a scrubber `<input type=range>`; auto-advances one frame every 900ms while playing.
- **Outputs per frame:** step counter, cumulative observation count, cumulative peak FRP, footprint radius, observation timestamp, and a live `RiskBadge` (severity + score) that updates frame-by-frame.
- **Backend/API:** `GET /api/events/{id}/replay` → `app/intelligence/replay.py::build_replay`, built on the same `evolve_event()` stepper as the Risk Trajectory (re-runs event-formation + deviation + classification + risk on successive real-observation prefixes — nothing interpolated).
- **Status:** IMPLEMENTED, real deterministic computation (`EventReplay.is_deterministic: true`).
- **Worth preserving:** MUST — this is one of the most distinctive, "wow-factor" interactions in the app (see §11).

### Facilities list + detail
- **Purpose:** browse monitored industrial facilities and drill into one.
- **Where it appears:** `/facilities` (card grid) and `/facilities/[facilityId]` (detail: header + map + "View full Thermal Twin profile" link + that facility's event grid).
- **Backend/API:** `GET /api/facilities`, `GET /api/facilities/{id}`, `GET /api/facilities/{id}/events`, `GET /api/facilities/{id}/thermal-twin` (caught/nulled if 404).
- **Status:** IMPLEMENTED.
- **Worth preserving:** NICE — solid but conventional; the real value is the linked Thermal Twin.

### Thermal Twins list + detail ("Facility Thermal Profile")

- **Where it appears:** `/thermal-twins` (list, inline custom cards — **note:** the reusable `ThermalTwinCard.tsx` component exists but is **not used** here; the list page reimplements an equivalent card inline instead) and `/thermal-twins/[facilityId]` (full profile via `FacilityThermalProfile`).

- **Backend/API:** `GET /api/facilities/{id}/thermal-twin`, `GET /api/thermal-twins` (list-all), `GET /api/facilities/{id}/events`.
- **Status:** IMPLEMENTED, real robust-statistics computation (`app/intelligence/thermal_twin.py`).
- **Worth preserving:** MUST (the hour-of-day chart + INSUFFICIENT-baseline honesty banner are distinctive); flag the unused `ThermalTwinCard` component for cleanup/reuse.

### Reports
- **Purpose:** bulk data export + on-demand full incident report generation.
- **Where it appears:** `/reports`.
- **Interaction:** two static download links (CSV, GeoJSON, via plain `<a href>`), plus an event picker + "Generate" button that calls the incident-report endpoint, renders the JSON inline in a scrollable `<pre>`, and offers a client-side "Download full report (JSON)" (`Blob` + object URL, no server round-trip for the download itself).

- **Worth preserving:** MUST.

### Model page
- **Purpose:** full transparency on the ML classifier's training methodology and performance.
- **Where it appears:** `/model`.
- **Outputs:** a loud amber "Proxy-label model" disclaimer banner, 5 KPI tiles, a per-class precision/recall/F1 table, a confusion matrix table, a feature-importance bar list, and a bulleted "Caveats" panel (⚠ icon per line).
- **Backend/API:** `GET /api/analytics/risk` (reuses `model_metrics` from the risk-analytics payload — the Model page has no dedicated endpoint of its own).
- **Status:** IMPLEMENTED, and unusually forthright for a "Model" page — it actively argues against over-trusting its own numbers.
- **Worth preserving:** MUST — the honesty framing here is a differentiator, not boilerplate.

### Fire Intelligence Agent
- **Purpose:** a deterministic, read-only natural-language query console over all computed OrbiFlare data.
- **Where it appears:** `/agent`.
- **Interaction:** chat-style turn list, 3 suggestion chips, free-text input; agent replies with text + optional result cards + an optional "Open investigation →" / "Open facility →" deep link.
- **Inputs:** a natural-language `message` string only — no structured query language, no SQL, no arbitrary parameters.
- **Backend/API:** `POST /api/agent/query` → `app/agent/runtime.py::run_query` (intent parse → controlled tool call → templated text + `ResultCard[]` + `UIAction`).
- **Read-only tool registry** (`app/agent/tools.py::TOOL_REGISTRY`, 19 tools): `list_events`, `get_event`, `get_investigation`, `get_facility`, `get_thermal_twin`, `get_deviation`, `get_evidence`, `get_risk`, `get_trajectory`, `compare_events`, `compare_facilities`, `list_high_risk_events`, `list_escalating_events`, `list_persistent_events`, `facility_event_frequency`, `get_event_statistics`, `get_facility_statistics`, `get_risk_statistics`, `compare_event_to_baseline`, `generate_report`.
- **Status:** IMPLEMENTED, fully deterministic (no LLM anywhere in the path — verified by an automated test asserting exactly one route exists under `/api/agent` and that no `llm_used`-style field exists in the response schema). Enforced read-only at multiple levels: no mutating tool names, a dedicated test that DB state is byte-identical before/after a battery of queries including a SQL-injection-shaped message.
- **Worth preserving:** MUST — the whole "analyst console, not ChatGPT" framing, the deep-link-back-to-investigation pattern, and the read-only guarantee are all strong and worth carrying forward as-is.

### Limitations page
- **Purpose:** a first-class, static, itemized accounting of every material limitation of the current build.
- **Where it appears:** `/limitations`.
- **Content:** 13 numbered limitation cards (VIIRS/MODIS resolution, false positives, source ambiguity, ground-truth availability, proxy labels, OSM incompleteness, proximity≠causation, baseline availability, ML uncertainty, satellite revisit cadence, historical-archive limits, clustering sensitivity, operator-validation requirement) + a "What OrbiFlare never claims" bullet list (5 explicit ✗ statements).
- **Status:** IMPLEMENTED (fully static content, hardcoded array — not derived from live data, and that's appropriate for its purpose).
- **Worth preserving:** MUST — this is a genuine product-honesty feature, not boilerplate, and is unusual to see as a first-class nav item.

### Operator Action / Alert Lifecycle
- **Purpose:** explicit, audited human state transitions for an event's alert status.
- **Where it appears:** bottom of the Investigation page (`OperatorActionsSection` → `OperatorActions`).
- **States/transitions:** `DETECTED → {VALIDATING, ALERTED}`, `VALIDATING → {ALERTED, MONITORING, EXTINGUISHED}`, `ALERTED → {ESCALATED, MONITORING, EXTINGUISHED}`, `ESCALATED → {MONITORING, EXTINGUISHED}`, `MONITORING → {ESCALATED, EXTINGUISHED, ALERTED}`, `EXTINGUISHED → {}` (terminal).
- **Backend/API:** `POST /api/events/{id}/transition` → `app/alerts/lifecycle.py::transition`, which raises `InvalidTransitionError` (409) for a disallowed edge and `ForbiddenActorTransitionError` (403) if `actor` looks like `"agent"/"ai"/"system"` and the target state is `EXTINGUISHED` — this is enforced in code, not just convention.
- **Status:** IMPLEMENTED, fully audited (`AlertHistoryRecord`, exposed via `GET /api/alerts/{id}/history`, not yet surfaced in any frontend screen — see §11/§15).
- **Worth preserving:** MUST — the code-enforced "agent can never resolve an incident" rule is a core trust guarantee of the product.

### Confirmed Incident tracking (backend-only, unexposed)
- **Purpose (inferred from code):** record an explicit human confirmation of an incident, separate from the alert-state machine.
- **Where it appears:** `app/alerts/store.py::confirm_incident()`, backed by `ConfirmedIncidentRecord` (`app/storage/models.py`).
- **Status: SCAFFOLDED / NOT WIRED.** No API route calls `confirm_incident`, and no frontend component references it. This is backend-complete but has zero surface area.
- **Worth preserving:** NICE TO PRESERVE conceptually (it's a reasonable feature — a stronger, more deliberate confirmation than a lifecycle transition) but it needs an actual route + UI to be a real feature, not dead code.

### OSM live fetch (backend-only, opt-in, unexposed)
- **Purpose:** live Overpass-API query for industrial land-use polygons near a bbox.
- **Where it appears:** `app/ingestion/osm.py::fetch_industrial_landuse(bbox, fetch_live=True)`.
- **Status: IMPLEMENTED but NOT WIRED.** No script or route ever calls it with `fetch_live=True`; the only facility-ingestion paths actually exercised are the static GeoJSON/WRI-CSV loaders (`app/ingestion/facilities.py`, via the newly-added `scripts/ingest_facilities.py`) and the DEMO fixture generator. Returns an explicit `OSMContextResult(available=False, reason=...)` when not fetched live — never a silent empty success.
- **Worth preserving:** NICE — same pattern as the FIRMS live wiring; would need a similar script/route to actually become live.

### Satellite imagery adapter (interface-only placeholder)
- **Purpose:** a documented extension point for a future imagery provider (Sentinel Hub, Planet, etc.).
- **Where it appears:** `app/ingestion/satellite.py::get_imagery_for_location()`.
- **Status: PLACEHOLDER.** Always returns `SatelliteImageryResult(available=False, reason="No satellite imagery provider is configured in this deployment.")`. Referenced by the Evidence Stack's standing `no_visual_confirmation` uncertainty item. Honestly labelled, not faked.
- **Worth preserving:** DO NOT CARRY FORWARD as-is (it's a no-op), but the *pattern* — an explicit typed "unavailable" result rather than a fabricated one — is worth preserving as a convention.

# 4. DESIGN SYSTEM

**Palette** (`frontend/tailwind.config.ts`, extended, dark-mode-only — `darkMode: "class"`, `<html class="dark">` hardcoded):
- `base` scale (950→100, near-black to light-grey): `950 #0a0c0f`, `900 #0e1116`, `850 #12151b`, `800 #171b22`, `700 #1f242c`, `600 #2a3038`, `500 #3a4149`, `400 #5a6169`, `300 #7d848c`, `200 #a8adb3`, `100 #d4d7da`.
- `accent`: `DEFAULT #3fd0e0` (cyan), `dim #1f8f9e`, `bright #7ce8f2` — used for the logo glow, active-nav highlight, focus rings, chart accent fill, links, and the primary action button.

# 7. EVENT / INVESTIGATION EXPERIENCE

Tracing the exact implemented workflow, in order:

1. **Finds an event** — via the Command Center priority feed, the Events grid (filtered/sorted), a facility's or twin's event grid, the map (any screen with `MapPanel`), the Agent (`list_high_risk_events`/`list_escalating_events`/`list_persistent_events`/`list_events` results), or a direct `/investigation/{id}` URL.
2. **Opens an event** — click navigates to `/investigation/[eventId]`; the whole page is one server-side call to `GET /api/events/{id}/investigation`, which 404s → Next's `notFound()` boundary if the id doesn't exist.
3. **Views event details** — `InvestigationHeader` (id, provenance badge, status, classification, coordinates, first/last-detected) + the "Event Summary" panel (facility context sentence, classification, peak/mean FRP, duration, observation count, footprint radius).
4. **Views observations** — `EventTimeline`, a Recharts line chart of FRP over time across every real observation (mono time-axis labels), placed directly under the map inside the same panel.
5. **Views facility context** — the Event Summary's "Facility context" row ("No facility within context radius" or "{name} (~X km away)") and the map itself, which plots the facility marker alongside the event marker.
6. **Views historical behaviour** — the "Facility Thermal Twin — Normal vs. Current" panel (`DeviationTable`), shown only if both a twin and a deviation exist.
7. **Views deviation** — `DeviationTable`: one row per dimension (FRP/intensity, Persistence, Duration, Timing, Spatial footprint, Recurrence), columns Current / Normal / Deviation-label (Normal/Notable/Significant, colour-coded), plus a free-text explanation list below the table (only the notable/significant dimensions' explanations, from `deviation.explanations[]`). If baseline is `INSUFFICIENT`, every row renders `"--"` and `"Insufficient baseline"` rather than a fabricated number.
8. **Views evidence** — "Why Flagged?" panel (`EvidenceStackView`): four conditionally-rendered sections (Supporting ✓ green / Contradicting-or-within-normal-range • grey / Uncertainty ⚠ amber / Unavailable – grey), each item shown as `[CATEGORY] explanation`, plus a boxed "Correlation notes" callout when applicable.
9. **Views ML information** — "ML Evidence" panel: two big percentage tiles (P(persistent industrial), P(natural/agri candidate)), a low-confidence warning line when applicable, a top-4 feature-importance mini-bar-chart, and a footer line naming the model version and pointing to the Model page for full caveats.
10. **Views risk** — inline inside the "Risk Trajectory" panel: `risk.explanation` (the named-factor sentence, e.g. "Driven primarily by: Ml Signal (+5), Persistence (+4).") plus every `risk.caveats[]` line rendered as a muted footnote.
11. **Views risk trajectory** — `RiskTrajectoryChart`: a compact numeric sequence header (`29 → 39 → ... → 74`) + `TrajectoryBadge`, above a Recharts gradient-filled area chart of risk score over time (0–100 fixed y-domain).
12. **Uses replay** — a text link out to `/replay/{event_id}` (a separate page, not a modal/inline expansion) — see §3.
13. **Takes an operator action** — the bottom "Operator Action" panel: current-state line + a row of buttons for every currently-legal transition (labelled with human verbs: Validate/Alert/Escalate/Monitor/"Resolve / Extinguish"), each a direct `POST /api/events/{id}/transition` with `actor: "operator"` hardcoded client-side; on success the local `state` updates in place (no page reload); on failure an inline red error line appears; a fixed disclaimer sentence is always shown ("...the system never autonomously marks an event Extinguished.").
14. **Generates a report** — not from the Investigation page itself; the analyst navigates to `/reports`, picks the event from a dropdown, clicks Generate, and gets the full JSON incident report inline + downloadable.

Also present but not in the numbered list above: an "Alternative Explanations" panel (primary hypothesis + possible alternatives + unknowns, rendered as three stacked sub-sections) and a conditional amber "Uncertainty" notice block (`UncertaintyNotice`) fed by `investigation.uncertainty_notes[]`.

# 9. INTELLIGENCE / AI / ML

Classification by category, matching the task's required distinction:

**REAL ML:**
- Random Forest classifier (`sklearn.ensemble.RandomForestClassifier`, `n_estimators=200, max_depth=8, min_samples_leaf=5, class_weight="balanced"`), 2 classes only (`PERSISTENT_INDUSTRIAL_THERMAL_SOURCE`, `NATURAL_AGRICULTURAL_FIRE_CANDIDATE`), 7 engineered features (`bt_kelvin, frp_mw, persistence_count, dist_nearest_facility_km, agri_season_flag, day_night_bin, acq_month`), trained on a **synthetic, proxy-labelled** corpus (`generate_synthetic_training_corpus`, heuristic label = `dist<=5km AND persistence>=2`, with ~16% injected label noise and ~20–25% feature noise), evaluated on a **random hold-out** (2 of 10 synthetic "regions" excluded from training entirely). This is genuinely real, trained, evaluated ML — but explicitly and repeatedly labelled as trained on proxy labels, not verified ground truth (`is_proxy_label_model=True` travels with every prediction).

**REAL DETERMINISTIC LOGIC (the bulk of the "intelligence layer"):**
- **Event formation** — deterministic union-find spatio-temporal clustering (`app/intelligence/events.py`), stable/deterministic `event_id` (SHA1 hash of sorted member observation ids).
- **Facility enrichment** — `BallTree` (haversine) nearest-facility lookup, 15km context cutoff, never causal.
- **Facility Thermal Twin** — robust statistics (median/MAD/IQR/percentile) over historical events, explicitly excluding the current event from its own baseline, 3-tier confidence (ESTABLISHED/LIMITED/INSUFFICIENT) via config-driven thresholds.
- **Behaviour Deviation Engine** — 6 independent dimensions, robust z-scores (MAD-based, IQR fallback), `is_notable`/`is_significant` threshold classification (config: 1.5/3.0).
- **Evidence Fusion** — rule-based bucketing (supporting/contradicting/uncertain/unavailable) + explicit correlation-note generation when two evidence items share an underlying signal.
- **Alternative Explanations** — a pure branching function over (baseline presence, notable-dimension count, facility presence, ML class+confidence) producing a primary hypothesis + alternatives + unknowns; no learned model, no calibrated probability.
- **Risk Engine** — a fixed-weight linear combination of 6 named sub-scores (deviation 35% / ML 15% / persistence 15% / duration 15% / intensity 10% / facility-context 10%), threshold→severity lookup.
- **Risk Trajectory & Event Replay** — both literally re-run the entire above pipeline on successive real-observation prefixes (`evolve_event()`); trend classification (STABLE/INCREASING/ESCALATING/DECREASING/INSUFFICIENT_DATA) is a simple net-change + monotonicity rule, not a model.
- **Alert lifecycle** — a hand-coded state-transition graph + an explicit code-level rule forbidding the agent from setting `EXTINGUISHED`.
- **Fire Intelligence Agent** — regex/keyword intent + entity extraction (`app/agent/deterministic.py`), dispatched to a fixed tool registry; **zero ML/LLM inference anywhere in this path**.

**MOCK/DEMO:**
- `app/ingestion/demo_fixtures.py::generate_demo_dataset()` — the *only* fabricated data source in the whole codebase, generating 4 hand-authored scenarios (escalating refinery, stable steel plant, insufficient-baseline chemical plant, unassociated agricultural candidate) explicitly labelled `is_demo=True`/`source=DEMO`. Everything computed *from* this data (twins, deviation, evidence, risk, trajectory) is the same real pipeline as for live data — only the raw inputs are synthetic.

**STATIC UI (no computation, hand-authored content):**
- The Limitations page's 13 limitation cards and "never claims" list.
- The Model page's disclaimer banner text and caveat bullets (though the underlying metrics themselves are real, computed values).

**Explainability, confidence, uncertainty — concretely, not just claimed:**
- Every `Risk` carries `risk_factors[]` (named + weighted + explained) and `caveats[]`.
- Every `MLPrediction` carries `low_confidence` (threshold 0.55) and `feature_importance`.
- Every `Deviation` dimension carries `robust_z`, `is_notable`, `is_significant`, and a plain-English `explanation`.
- A dedicated `app/intelligence/explanations.py` module centralizes banned-phrase avoidance ("confirmed fire", "detected a fire", "facility caused", "caused by the facility", "will become a fire", "fire probability") — this is an enforced convention module, not just a style guide.

# 11. UNIQUE / INTERESTING FEATURES

- **Event Replay ("PLAY EVENT").** WHAT: a full transport-controlled player (play/pause/step/scrub) over an event's real observation history. WHERE: `/replay/[eventId]`. HOW: each "frame" is a full re-run of deviation+classification+risk on the observations-so-far, so the risk badge and cumulative stats genuinely change frame-by-frame rather than interpolating between two known states. WHY useful: lets an analyst *watch* an event's behavioural signature emerge, rather than only seeing the final aggregate — directly supports the "explainable trajectory, not a single verdict" pitch.

- **Risk Trajectory built on the same engine as Replay.** WHAT: both features share one `evolve_event()` stepper (`app/intelligence/trajectory.py`). WHERE: Investigation page chart + Replay player. HOW: guarantees the trajectory chart and the replay player can never disagree about what happened at any point in an event's history — a genuine architectural integrity feature, not just a UI coincidence.

- **INSUFFICIENT-baseline honesty, enforced end-to-end.** WHAT: when a facility doesn't have enough history, every downstream artifact (Thermal Twin badge, Deviation table cells, Risk caveats, Investigation uncertainty notes, the Agent's `compare_event_to_baseline` reply) says so explicitly instead of guessing. WHERE: visible on the Synthetic Chemical Plant Gamma demo scenario specifically (designed to demonstrate this). WHY useful: this is the single clearest, most consistently-threaded "we will not fabricate" guarantee in the whole product.

- **Evidence Fusion's correlation-note mechanism.** WHAT: explicit detection and disclosure that the ML signal and the intensity-deviation signal are correlated (both FRP-driven) so they aren't double-counted as independent confirmation. WHERE: Investigation "Why Flagged?" panel, boxed callout. WHY useful: a real, specific epistemics feature that most "evidence panel" UIs never bother to implement — it's not just listing evidence, it's reasoning about evidence independence.

- **Alternative Explanations as a first-class artifact.** WHAT: a primary hypothesis + genuine alternatives + unknowns, generated by a pure branching function, not a single forced verdict. WHERE: Investigation page, dedicated panel. WHY useful: directly counters the "black box says fire" failure mode common to this category of product.

- **Programmatically agent-forbidden state.** WHAT: `app/alerts/lifecycle.py::ForbiddenActorTransitionError`, raised specifically when `actor` looks like an AI/system and the target is `EXTINGUISHED`. WHERE: enforced in `transition()`, exercised by a passing backend test. WHY useful: a concrete, testable trust boundary rather than a documentation promise.

- **Deterministic, replayable IDs.** WHAT: `event_id` is a stable SHA1 hash of its sorted member observation ids; `observation_id` is a stable hash of source+sensor+rounded-coords+timestamp. WHERE: `app/intelligence/events.py`, `app/preprocessing/normalization.py`. WHY useful: re-running the pipeline on the same raw data always reproduces the same events/observations — genuinely deterministic, testable behaviour (verified by `test_clustering_is_deterministic_across_runs`).

- **Dark-basemap trick via CSS filter, not a paid vector tile provider.** WHAT: `invert(1) hue-rotate(180deg) brightness(0.92) contrast(0.9) saturate(0.5)` applied only to the raster canvas (markers/popups excluded). WHERE: `globals.css` + `MapPanel`. WHY useful: gets a fully dark, on-brand map with zero API keys and zero paid dependency — a clever, low-cost visual-polish solution.

- **Analyst-console agent, not a chat product.** WHAT: compact result-card previews (title/subtitle only), deep-link buttons instead of inline data dumps, suggestion chips instead of a prompt library, and (as of this version) zero "AI branding" — no avatar, no streaming-typewriter effect, no model-name badge. WHERE: `/agent`. WHY useful: matches the product's own stated design goal ("avoid making it look like ChatGPT... feel like an analyst console").

- **Hand-rolled feature-importance bar visualization.** WHAT: plain flexbox divs used as proportional bars (no chart library) on both the Investigation ML panel and the Model page. WHY interesting: a small but deliberate choice to keep a simple visualization dependency-free.

# 15. FINAL DESIGN DNA

## WHAT MAKES THIS VERSION FEEL DISTINCTIVE?

1. It reads as an **operator console for a serious analyst**, not a marketing dashboard — dense small type, no hero sections, no large illustrative graphics, Unicode glyphs instead of an icon library.
2. Its honesty mechanisms are **implemented as code, not just copy** — INSUFFICIENT baseline propagates through five different UI surfaces identically; the agent's read-only guarantee is enforced and tested, not just described.
3. **Provenance is a first-class visual signal** everywhere an event/observation appears (Demo vs. Live badges), never left implicit.
4. The **same deterministic stepper** (`evolve_event`) powers two seemingly different features (Risk Trajectory chart and Event Replay player), so they can never contradict each other — an architecture decision that is directly visible as a UX guarantee.
5. Every chart uses the exact same dark tooltip/grid/axis styling and the same accent colour — there is no chart-library visual drift anywhere in the app.
6. The Fire Intelligence Agent deliberately avoids every visual signifier of "AI chat" (no avatar, no streaming text, no model badge) in favor of a compact, card-preview, deep-link-driven console.
7. A single `Panel` primitive is reused for literally every container in the app — no competing card/box styles anywhere.
8. Two pages (Limitations, Model) exist purely to argue against over-trusting the product's own outputs — a deliberate anti-hype stance baked into the navigation itself.

## TOP FEATURES TO CARRY INTO FINAL ORBIFLARE
1. Event Replay's real-recompute playback (and its shared engine with Risk Trajectory).
2. The Facility Thermal Twin honesty model (ESTABLISHED/LIMITED/INSUFFICIENT) threaded end-to-end.
3. The Evidence Stack's correlation-note mechanism.
4. Alternative Explanations as a distinct, non-verdict artifact.
5. The deterministic, tool-registry-based, LLM-free Fire Intelligence Agent.
6. The code-enforced agent-cannot-extinguish rule + audited operator-action lifecycle.
7. The unified design system (`Panel`, tinted-pill badges, mono-for-data, dark CSS-filtered basemap).
8. Explicit Demo-vs-Live provenance badging on every relevant surface.
